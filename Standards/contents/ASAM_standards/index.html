    ASAMで生きている規格

    ここでは 「ASAMが策定しており、2026年時点でも“現役で使われている規格”」 を、実務での使われ方が分かるカテゴリ分けで整理します。
    ※「歴史的には存在するが、現在ほぼ使われていない／後継に置き換わったもの」は除外または注記します。

    根拠は ASAM 公式が現在も Standards ポートフォリオとして維持・更新している規格群です。

    ASAM 現役規格の全体カテゴリ

    ASAM公式では、現在の規格を以下 7カテゴリ に分類しています。

    1. Measurement & Calibration（計測・適合）
    2. Diagnostics（診断）
    3. ECU Networks（ECUネットワーク）
    4. Software Development（ソフトウェア開発）
    5. Test Automation（テスト自動化）
    6. Data Management & Analysis（データ管理・解析）
    7. Simulation（OpenX系：シミュレーション）

    以下、それぞれについて 「今も使われている規格」だけを説明します。

    1. Measurement & Calibration（計測・適合）

    最も成熟しており、現場での使用率が非常に高いカテゴリ

    ✅ 現役主要規格

    • ASAM MCD-1 XCP

      • ECU内部変数・パラメータへのアクセスプロトコル
      • CAN / FlexRay / Ethernet などバス非依存
      • 事実上の業界標準 [vector.com]

    • ASAM MCD-2 MC（A2L）

      • ECUメモリ・変数・マップのメタ記述
      • XCP/CCPと常にセットで使用

    • ASAM MDF

      • 計測データ保存フォーマット（大量データ向け）
      • 計測・HIL・車両ログで広く使用

    • ASAM CDF

      • キャリブレーションデータ交換用フォーマット
      • ツール間・組織間データ交換で使用

    • ASAM ACI

      • 自動適合（ACS ↔ TAS）のインターフェース
      • エンジン・モータ適合の自動化用途 [blog.csdn.net]

    ⚠️ 補足

    • CCP は今も存在するが、新規設計では XCP が主流

    2. Diagnostics（診断）

    UDS世代の診断をツール・テスト視点で支える規格群

    ✅ 現役主要規格

    • ASAM MCD-2 D

      • 診断サービス・データの記述（ODX）
      • UDSベースの診断設計・試験に必須

    • ASAM MCD-3 D

      • 診断テスト・シーケンス定義
      • 診断自動試験で使用

    • ASAM SOVD

      • Service-Oriented Vehicle Diagnostics
      • SDV / OTA 時代向けの次世代診断

    3. ECU Networks（ECUネットワーク）

    通信仕様そのものではなく「設計・テスト記述」が中心

    ✅ 現役主要規格

    • ASAM MCD-2 NET
      • ECUネットワーク構成・通信の記述
      • テスト・検証用途で利用

    4. Software Development（ソフトウェア開発）

    AUTOSARと補完関係にある設計・要求系規格

    ✅ 現役主要規格

    • ASAM CC

      • コンポーネント・アーキテクチャ記述

    • ASAM FSX / MBFS

      • 機能安全・モデルベース設計支援

    • ASAM ISSUE

      • 不具合・変更要求の標準記述

    いずれも プロセスを直接規定しない「実装寄り標準」。

    5. Test Automation（テスト自動化）

    HIL・SIL・ベンチ試験の共通化

    ✅ 現役主要規格

    • ASAM XIL / XIL-MA

      • HIL / SIL / MIL 環境の抽象化インターフェース
      • テスト資産の再利用に必須

    • ASAM ASAP3

      • テストシステム制御API
      • 古参だが今も使われている

    • ASAM OTX

      • テストシナリオ記述言語
      • 診断・ECUテストで現役

    6. Data Management & Analysis（データ管理・解析）

    JAIGや日本OEMが特に重視してきた領域

    ✅ 現役主要規格

    • ASAM ODS

      • 計測・試験・運用データの統合管理
      • 大規模OEMでは事実上の標準

    • ASAM CEA

      • データ交換・解析支援
      • ODS周辺で使用

    7. Simulation（ASAM OpenX 系）

    ADAS / 自動運転で急成長中のカテゴリ

    ✅ 現役主要規格

    • ASAM OpenDRIVE
      • 道路ネットワーク記述
    • ASAM OpenSCENARIO (XML / DSL)
      • シナリオ記述（動的挙動）
    • ASAM OSI
      • シミュレーション間インターフェース
    • ASAM OpenCRG
      • 路面詳細形状

    いずれも 現在も活発に更新・採用が進行中。

    まとめ（実務視点）

    「今も本当に使われている」中核規格

    • XCP / A2L / MDF
    • ODX (MCD-2 D)
    • ODS
    • XIL
    • OpenDRIVE / OpenSCENARIO

    「ASAMを学ぶ＝これを理解する」

    と言ってよい構成です。

    ---

    今は使われなくなったASAM規格

    いい切り口です。
    ここでは **「ASAMが過去に策定したが、2026年時点では新規採用・主流利用がほぼ無く、実質レガシー扱いになっている規格」**を、理由付きで一覧化します。

    ※重要な前提として
    ASAMは ISOのように公式な“廃止（Withdrawn）宣言”をほとんど出しません。
    そのため以下は、

    ✅ ASAM公式ポートフォリオ上は存在する
    ✅ しかし実務では後継規格に置き換わり、新規案件で使われない

    という意味での「使われなくなっている規格」です。

    使われなくなっている（レガシー）ASAM規格一覧

    1. Measurement & Calibration 系

    ❌ ASAM MCD-1 CCP

    （CAN Calibration Protocol）

    • 状態：レガシー

    • 理由

      • バス依存（CAN前提）
      • 帯域・拡張性に限界
      • XCPが完全上位互換

    • 現状

      • 既存ECUの保守用途のみ
      • 新規設計では ほぼ100% XCP

    ASAM自身も MCD-1 XCP を主軸に据えています。 , [vector.com]

    ❌ ASAM ARTI（旧名義）

    • 状態：名称・位置づけ変更により実質消滅
    • 理由
      • 機能が MDF / TDF に再編
    • 現状
      • ドキュメント上は「TDF (formerly ARTI)」として吸収

    👉 ARTI単体を学ぶ必要は無い。

    2. Diagnostics 系

    ❌ ASAM MCD-3 D（単独利用）

    • 状態：部分レガシー

    • 理由

      • 診断テスト記述としては存在
      • しかし
        • OTX
        • 各社独自フレームワーク に置き換えられるケースが増加

    • 現状

      • ODX（MCD-2 D）は必須
      • MCD-3 D は限定用途

    ASAM Diagnostics ドメインの中心は MCD-2 D と SOVD に移行。

    3. ECU Networks 系

    ❌ ASAM MCD-2 NET

    • 状態：ほぼ使われていない

    • 理由

      • AUTOSAR / 各社ネットワーク記述に吸収
      • 単独で使う価値が薄い

    • 現状

      • 一部ツール互換・研究用途のみ

    ASAM公式ポートフォリオには残るが、実務採用例は稀。

    4. Software Development 系

    ❌ ASAM LXF

    • 状態：レガシー

    • 理由

      • モデル・仕様記述用途
      • AUTOSAR / SysML / 各社MBSEに置き換え

    • 現状

      • 新規導入事例はほぼ無し

    ❌ ASAM ISSUE（単独運用）

    • 状態：部分レガシー

    • 理由

      • 変更管理・課題管理用途
      • 実務では
        • Jira
        • Polarion
        • CodeBeamer 等に統合

    • 現状

      • 「思想」は残るが、規格としての採用は稀

    ASAMはプロセス系ツールを主戦場にしていない。

    5. Test Automation 系

    ❌ ASAM ASAP2 / ASAP3（設計新規用途）

    • 状態：レガシー寄り

    • 理由

      • 古いAPI設計
      • 柔軟性が低い
      • XIL / OTX に役割移行

    • 現状

      • 既存設備の維持用途
      • 新規HILでは XIL が主流

    ❌ ASAM ATX / GDI（単体）

    • 状態：実質統合・吸収
    • 理由
      • XIL / OTX / 各社APIに吸収
    • 現状
      • 単独で名前が出ることはほぼ無い

    6. Data Management & Analysis 系

    ❌ ASAM CEA（単独利用）

    • 状態：ほぼ使われていない

    • 理由

      • ODS が完全に主役
      • CEAはODSの補助的役割に縮小

    • 現状

      • ODSを学べば十分

    ASAM ODS がこのカテゴリの事実上の標準。

    7. Simulation 系（OpenX 以前）

    ❌ ASAM OpenCRG（主役扱い）

    • 状態：補助規格化

    • 理由

      • 路面詳細特化
      • OpenDRIVE / OpenSCENARIO / OSI が主役

    • 現状

      • ニッチ用途では現役
      • しかし OpenX の中心ではない

    一覧まとめ（実務視点）

    ✅ 「もう学ばなくてよい」規格

    MCD-1 CCP
ARTI（旧）
MCD-2 NET
LXF
ASAP2（新規用途）

    ⚠️ 「存在は知るが深追い不要」

    MCD-3 D
ISSUE
CEA
OpenCRG

    ✅ 「完全に現役」

    XCP
A2L (MCD-2 MC)
MDF
ODX (MCD-2 D)
ODS
XIL
OpenDRIVE / OpenSCENARIO / OSI

    重要な整理（結論）

    ASAMは

    • 古い規格を“消さない”
    • 新しい規格で“上書きする”

    という思想です。

    したがって学習・実務では：

    「ASAMポートフォリオに載っている」＝「使う」ではない

    という判断が必須です。
